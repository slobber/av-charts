# 性能与大批量读数

这一页的目的很窄：告诉你数字是多少、它们是在什么条件下量的、以及"觉得慢"的时候该动哪个旋钮。

## 数字

十万个读数、680×320 的绘图区、桌面机、BenchmarkDotNet（`dotnet run -c Release --project
src/AvCharts.Benchmarks`，完整的表与条件在[设计简报](https://github.com/slobber/av-charts/blob/master/docs/design-brief.md) §11）：

| 场景 | 实测 |
|---|---|
| 十万点画出第一帧（采样开） | 约 30ms |
| 拖窗一帧（窗口在动、抽稀留着用） | **3.7ms/帧**，651KB |
| 缩放一帧（每帧跨一次桶宽） | 4.1ms/帧 |
| 窗口在动 + 数据在流 | 4.4ms/帧 |
| 在十万点上做一次命中测试 | 约 70µs |
| 一万点合批追加（`ApplyPushed`） | 约 0.8ms |
| 一百万读数常驻（库自己留下的部分） | 约 24MB，即每点 24 字节；CI 的门禁是 < 50MB |

**只有同一会话内的倍数可读。** BenchmarkDotNet 会把机器切到高性能电源计划，跨会话的漂移可以有 ±30%，
换一台机器就更多。要比就跟同一次会话里的另一个数比，别拿这张表当承诺。

一个容易误读的细节：**拖动中的帧和静止的帧是同一条路径** —— `MinMax` 抽稀每一帧都画同一份抽稀结果
（拖窗只改窗口、不改桶宽），所以两帧逐像素相同（`DragThinningTests`）。没有"动起来才糊"这回事。

## 一帧的钱花在哪

一次重排 = 一次几何重建（十万点约 600KB 分配），绘制只是把已有的一份几何画出来。目前**平移一帧也会重建**
（约 4MB/帧的分配），把 min/max 包络缓存在数据空间、拖拽时只重映射包络的原型已经量过（一帧 10.3 → 4.7ms、
分配 4.15 → 0.21MB，代价是画面不再逐像素一致），但还没有入库 —— 它是[设计简报](https://github.com/slobber/av-charts/blob/master/docs/design-brief.md)
§14 的挂账项。同理，切换 light/dark 目前会重建几何（约 4.2MB 分配），和 §11 写的"不重建"对不上，也记在
§14 里。

## 该调什么旋钮

按"先看这一条"的顺序：

1. **开采样**。`series.Sampling = SamplingMode.MinMax`（或 `Average` / `Lttb`）。点数不超过像素列数时它
   自动不生效，所以"点少的时候"也不会白花时间。尖峰要保住就用 `MinMax`。
2. **有界窗口**。`series.MaxReadings = 5000`：只留最新的若干条，内存是一个常数。
3. **推送按帧合批**。数据从别的线程来，用 `Push` + 图表的每帧排空，而不是每来一个点就 `InvalidateData`；
   一批一百个点只触发一次失效。
4. **让失效留在它该在的层**。悬浮一个点重录一个图层，这是库的结构决定的，别在自己的元素里手动触发整图重画。
5. **固定尺度 + 等格**（心电图、示波器那种）：`AxisScaleMode.Fixed` + `PixelsPerUnit`，一个单位数据始终占
   那么多像素，滚动时不重新分配格子。
6. **数据侧的选择器尽量简单**。每个点都会被读一次：lambda 直接读属性最快，路径选择器（`XPath`/`YPath`）
   走的是反射，是给标记文件准备的。

## 线程

只有一条规矩，但它不能破：**系列的值只在绘制它的那个线程上被写**。所以：

- 在别的线程上取数 → `Push(record)`（内部加锁缓冲，什么也不画）；
- 图表在每一帧排空一次缓冲（`ApplyPushed`）；
- `Pushed` 是在**推送线程**上抛的，它的唯一用途是"请求一次 UI 线程的 pass"，处理器里不要画东西；
- `PendingPushes` 可以跨线程读，用来看排队有多深。

推入的记录会进入 `ItemsSource`，所以源必须**可加**（`ICollection<T>` 且非只读）。给一个数组，`Push` 会当场
抛错 —— 这比悄悄丢数据好，也比事后发现少了几百个点好。

## 内存

每点 24 字节：**单位空间里的两个 `double`**（16 字节，两个数组），外加**一份指向你自己的对象的引用**
（8 字节 —— 因为数据提示与事件要把记录交还给你，命中回来的 `Item` 就是你那个对象）。所以常驻内存 ≈
24 字节/点 + 你的记录本身。CI 里有一条门禁钉着它（一百万点 < 50MB，且把调用方自己的那 8MB 减掉）。
`ChartItem` 是惰性视图，遍历一百万个点不会造出一百万个对象。
