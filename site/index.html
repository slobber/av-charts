A charting library for Avalonia, modelled on Flex's mx.charts

Axes, series, transforms and a drawing kernel, named the way mx.charts names them and built for readings rather than for sample data: a hundred thousand of them drawn in about thirty milliseconds, with sampling, gaps, second scales, data tips and a legend that switches a series off.

A first chart

var chart = new CartesianChart
{
    HorizontalAxis = new DateTimeAxis(),
    VerticalAxis = new LinearAxis(),
};

chart.Series.Add(new LineSeries<Reading>
{
    DisplayName = "Depth",
    ItemsSource = readings,          // whatever you have: a list, an array, a collection
    XSelector = reading => reading.When,
    YSelector = reading => reading.Depth,
});

The two packages come from NuGet, and one line in a page's resources dresses every chart on it: <ResourceInclude Source="avares://AvCharts.Controls/Themes/ChartTheme.axaml" />. The longer version has the whole of it.

Against LiveCharts

The same hundred thousand readings, the same 680×320 plot, the same headless Skia, the same benchmark session on one machine - and both sides driven the way their own documentation says to drive them. LiveCharts has no thinning of its own, so "the same conditions" can only be either of the two things below.

Both sides asked to… LiveCharts 2.1.0-dev-798 AvCharts ratio
draw all hundred thousand readings 262 ms a frame 30 ms a frame about 8.8×
draw about 1,300 readings 9.1 ms a frame 2.0 ms a frame about 4.5×
thin them out first (AvCharts only: LiveCharts has no sampling) — 8.4 ms a frame

Read the ratios and not the milliseconds: they come from one session, and the same work on another machine - or under another power plan - moves by tens of per cent. LiveCharts' figures come from its own headless SKCartesianChart without the control layer, which counts in its favour, and from a pre-release build of it. Every number, its conditions and how to reproduce it are in the design brief, performance section.
